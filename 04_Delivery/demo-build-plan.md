## 1. The one claim the demo must prove

> "The Harness extracts behavioral specifications from real Fortran source, surfaces SME review with full traceability to source, signs an authoritative contract, and emits scaffolded target code with test fixtures derived from signed invariants."

That is the entire claim. The demo is *not* about polish, completeness, or scope. It is about **proving the pipeline works as a system, with humans in the loop, end-to-end, on real LLM calls, in 4 minutes.**

## 2. Demo flow (4 minutes, beat-by-beat)

| Time | Screen | Action | Audience takeaway |
|---|---|---|---|
| 0:00 – 0:30 | 2.1 Subroutine detail (Source tab) | Open `CONSUME_ROLL`; briefly call out it's representative Fortran/Classic code with COMMON, ISAM I/O, magic numbers. | This is real legacy code. |

| 3:45 – 4:00 | Audit close | Show commit-to-Git event in the audit log. Mention this scaffold flows into the Project 3 main build pipeline. | Integration with the broader programme is real, not theoretical. |

## 4. Live-demo risk mitigations (Appendix A.4, expanded)

### 4.1 Pre-recorded backup

A full recorded run of the demo flow is captured in week 6's third rehearsal. The recording lives on STAGING and a local backup. The recording is the canonical fallback per Appendix A.4.

**Trigger to switch to recording:** any of the following during the live demo:

- Stage 3 extraction exceeds **35 seconds** from "Extract spec" click.
- Any visible error surface (failure banner, "Provider returned…", network drop).
- The presenter's judgement.

**Switch handoff line (verbatim):** *"Let me show you this from our recorded run so we don't lose time."*

### 4.2 Two pre-warmed sessions

- **Session A (live):** primary browser, primary network. Full-screen, demo URL.
- **Session B (recorded):** secondary browser tab, ready to play. Full-screen, recorded URL.
- Both sessions tested at start-of-day; presenter has a tested keyboard cue (`Cmd-Tab` or window-manager shortcut) to switch.

### 4.3 Network independence

- Primary connection: venue ethernet (verified at venue setup).
- Fallback: tethered cellular (verified at start-of-day).
- DNS and routing tested for both providers (Anthropic + Azure OpenAI) on the fallback connection.

### 4.4 In-app safeties

- **60-second timeout** on the demo extraction call (overrides the production 120s default for the demo build).
- **Cached-fallback indicator.** If the timeout fires, the cached response from the most recent rehearsal renders with a "loaded from cache" indicator. Honest, not deceptive.
- **Failover OFF.** The recorded backup is more controllable than a runtime failover; runtime failover is disabled in the demo build's routing config.

### 4.5 Determinism

- Synthetic Fortran sample (`CONSUME_ROLL`) is committed once and never modified.
- Prompt template (`fortran-extract-v3.2`) is pinned for the demo corpus; iteration on this template is paused once week 5 begins.
- Provider parameters tuned for low temperature (0.1–0.2) so rehearsals produce comparable specs.
- Three rehearsals minimum in week 6; deltas reviewed and prompt parameters adjusted only if the deltas would confuse the audience.

## 9. Dress-rehearsal protocol (Phase B.5)

Three timed walkthroughs in the week before the defense call. Each one is recorded; the third recording is the live-demo backup per A.4.

### 9.1  Per-stage timing budget

| Stage | Soft target | Hard ceiling | What blows it up |
|---|---|---|---|
| 0:00 — Open Subroutine detail (2.1) | 25 s | 45 s | Source pane in Monaco taking >2 s to render (Phase B.4 fixed). |
| 0:30 — Live extraction (3.1) streams in | 60 s | 90 s | Real Anthropic latency. With the mock, this beat is 12 s — *the demo plays well below its budget*. |
| 1:30 — Spec review (4.2): SME accepts/edits/resolves | 50 s | 70 s | Slow keyboard / wrong shortcut. `J/K` to navigate, `A` accept, `E` edit. |
| 2:30 — Sign-off (modal + transition) | 20 s | 30 s | Forgetting to tick the canonical-sentence checkbox. |
| 2:50 — Audit trail glance | 15 s | 25 s | Click "Audit trail" from the toolbar; scroll once. |
| 3:00 — Scaffold streaming (5.1) | 30 s | 50 s | Mock takes 6 s; real Azure OpenAI ~25 s. |
| 3:30 — Scaffold artifact (5.2) walk | 30 s | 45 s | Linger on traceability panel: hover one TODO, show "derived from INV-1, INV-3". |
| 3:45 — Commit + audit close | 15 s | 25 s | Click commit; show the chip; switch to audit; point at `scaffold.committed`. |
| **Total** | **3:45** | **5:30 (over budget)** | — |

The mock-provider runs comfortably inside the 4-minute window. If real-provider rehearsals push past 5:00 the recorded backup engages at the 35-second extraction watermark per A.4.

### 9.3  Pre-flight checklist (run before every rehearsal)

```bash
# 1. Confirm stack health
curl -sf http://127.0.0.1:38080/health/ready | jq '.status'   # expects "ready"

# 2. Reset the demo data deterministically
docker compose -f app/docker-compose.yml restart api          # rebuilds schema + seed
sleep 8                                                       # wait for seed to land

# 3. Run the E2E smoke test (validates the full flow before the audience does)
cd app/e2e && npm test                                        # ~25 s on mock provider

# 4. Open the demo browser tab
open http://127.0.0.1:35173/  # or 35173 IPv6/cache-bust as needed
```

If step 3 fails, the demo does not run — diagnose first. The Playwright test is the authoritative pre-flight gate.

### 9.4  Failure-mode rehearsal

In the same week, one rehearsal exercises each failure path with the recording rolling so the team has practiced recovery:

- **Provider 5xx mid-extraction** — toggle `Llm:Provider=fail-mock` (Phase B.5.1 — to be added) and recover on retry.
- **Network drop mid-stream** — disconnect the tethered fallback; SSE reconnect should buffer.
- **Sign already exists** — second presenter clicks Sign at the same time; modal must self-recover (idempotent path verified Phase B.5).
- **Schema-rebuild reset** — accidental `docker compose down -v`; rerun the pre-flight checklist.

### 9.5  Backup recording engagement

The third rehearsal's recording is the canonical backup. Trigger conditions:

- Any rehearsal beat exceeds 35 s for the extraction stream
- Any visible error banner during the live walk
- Presenter judgement (e.g. provider feels slow on first token)

Switch line, verbatim:
> "Let me show you that from our recorded run so we don't lose time."

### 9.6  Owner sign-off

Before the defense call, the eng-lead signs off on:

- [ ] All three timed rehearsals complete; recordings archived
- [ ] Pre-flight checklist runs green from a cold `docker compose up -d`
- [ ] E2E test (`app/e2e/`) green on CI and locally
- [ ] Idempotent sign + already-signed recovery verified (Phase B.5)
- [ ] Mock provider is the demo default; real Anthropic / Azure OpenAI are configured but require a manual flag flip
- [ ] Failover toggle is OFF (per A.4 — recorded backup is more controllable)
- [ ] Two pre-warmed browser tabs ready (live + recorded)
- [ ] Network independence verified on both connections
